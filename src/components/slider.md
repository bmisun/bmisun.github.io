## 의도

순환 이동, 인디케이터, 자동재생, 키보드 조작을 갖춘 슬라이더 컴포넌트 제작. 처음엔 "좌측정렬 + 1장씩 순환"이라는 단일 방식으로 시작했지만, 넷플릭스·교보문고 등 실제 서비스를 참고해 "화면에 보이는 만큼 페이지 단위로 이동"하는 방식과 "활성 슬라이드가 항상 가운데 오는" 중앙정렬 방식까지 필요해지면서, 하나의 컴포넌트가 여러 정렬·이동 방식을 속성만 바꿔 갈아 끼울 수 있는 구조로 확장했다.

### 구현 과제

1. 슬라이드마다 너비가 다를 수 있는(가변폭) 구조 지원
2. WCAG 2.2.2("자동으로 움직이는 콘텐츠는 사용자가 멈출 수 있어야 한다")를 고려한 자동재생 사용자 제어(hover 정지, 재생/일시정지 버튼)
3. 페이지에 슬라이더가 여러 개 있을 수 있는 다중 인스턴스 대비
4. 정렬(좌측/중앙)과 이동 방식(무한루프/페이지 단위)을 조합한 여러 타입을 하나의 컴포넌트로 지원
5. 마지막→처음 전환이 자연스러운 무한 루프(빈 화면·되감기처럼 보이는 끊김 없이)

## 구현 과정

### 이동 로직의 순서

`moveSlide(dir)`는 먼저 인덱스(또는 오프셋)를 원하는 방향으로 갱신한 뒤, 그 값으로 위치(`transform`)를 계산하는 순서를 원칙으로 고정했다. 순서가 바뀌면 슬라이드가 한 박자 늦게 반응하거나 엉뚱한 방향으로 이동하는 결과가 나온다.

### 가변폭 슬라이드의 오프셋 계산

슬라이드 너비를 `flex: 0 0 auto`로 가변화하는 구조라, 이동 거리는 "인덱스 × 고정폭"이 아니라 "0번부터 목표 인덱스 직전까지의 너비를 전부 더한 값"으로 계산해야 했다. `getOffset(index)`를 누적합 방식으로 작성했고, 매번 `offsetWidth`를 다시 읽는 대신 초기화 시점에 너비 배열(`slideWidths`)을 한 번만 캐싱했다. 중앙정렬 타입에서는 이 누적합에서 `(컨테이너 폭 - 해당 슬라이드 폭) / 2`를 한 번 더 빼서, 활성 슬라이드가 항상 컨테이너 가운데 오도록 보정했다. 정렬 방식이 달라져도 "누적합"이라는 계산 뼈대 자체는 그대로 재사용된다.

### 클론(cloneNode) 복제 방식의 무한 루프 — 왜 "전체 세트"인가

처음엔 순환 이동 시 인덱스만 `% slides.length`로 감아서 마지막에서 처음으로 넘어갈 때 트랙이 오른쪽 끝에서 왼쪽 끝까지 역방향으로 "빠르게 되감기"하는 것처럼 보이는 문제가 있었다. 첫 시도로 첫/마지막 슬라이드를 1장씩만 `cloneNode`해서 트랙 앞뒤에 붙여봤지만, 슬라이드 폭이 컨테이너보다 훨씬 좁아 원래도 "다음 슬라이드 일부가 옆에 걸쳐 보이는(peek)" 구조였기 때문에, 복제본 1장 뒤에 다시 빈 공간이 남는 문제가 생겼다. 최종적으로는 슬라이드를 1장이 아니라 **전체 세트를 통째로 한 번 더 복제**해서 뒤에 붙이는 방식(`1,2,3 → 1,2,3,1,2,3`)으로 바꿨다. 어느 위치에서 peek이 발생해도 그 자리에 항상 실제 또는 복제 콘텐츠가 채워져 있어 빈 공간이 생기지 않는다. 마지막 실제 슬라이드에서 다음으로 넘어가면 복제 세트 쪽으로 자연스럽게 애니메이션하고, 트랜지션이 끝나는 순간 애니메이션 없이(`gsap.set`) 진짜 첫 슬라이드 위치로 순간 이동한다 — 복제본과 원본이 똑같이 생겨서 이 전환은 화면상 보이지 않는다(Swiper 같은 캐러셀 라이브러리의 무한 루프와 같은 원리). 중앙정렬 타입은 여기서 한 단계 더 나아가 **앞뒤 양쪽에 전체 세트를 복제**해서, 첫 슬라이드가 활성 상태여도 왼쪽에 빈 공간 없이 이전 방향으로도 순환할 수 있게 했다.

### 클론에 안전한 스타일 — `:nth-of-type` 대신 인라인 커스텀 프로퍼티

슬라이드별 너비/배경색을 처음엔 `&:nth-of-type(N)` 같은 순번 기반 선택자로 정의했는데, `cloneNode`로 슬라이드를 복제하면 복제본이 원본과 다른 순번에 위치하면서 스타일을 통째로 잃어버리는 문제가 생겼다. `--slide-width`/`--slide-bg` 인라인 커스텀 프로퍼티로 교체해 해결했다. `cloneNode(true)`는 인라인 `style`도 그대로 복사하므로, 복제본도 항상 원본과 같은 모양을 유지한다. "같은 컴포넌트인데 인스턴스/슬라이드마다 값이 다른" 요소는, DOM이 나중에 복제·재배치될 가능성을 염두에 두고 처음부터 순번 선택자가 아니라 인라인 커스텀 프로퍼티나 data 속성으로 값을 받는 편이 안전하다는 걸 확인한 경험이다.

### 정렬·이동 방식을 데이터 속성으로 분리

정렬(`data-align="start"|"center"`)과 이동 방식(`data-loop="infinite"|"pingpong"`)을 마크업의 data 속성으로 표현하고, JS(`setupSlider`)가 이를 읽어 오프셋 계산·클론 생성 로직을 분기하도록 설계했다. 시각적 스타일이 아니라 "이동 계산식이 달라진다"는 동작 차이라 BEM 모디파이어보다 data 속성이 더 맞다고 판단했다. 다만 순수 시각적 배치 차이 — 예를 들어 페이지 단위 타입에서 이전/다음 버튼을 슬라이더 좌우 끝에 고정하는 것 — 는 여전히 BEM 모디파이어(`.slider--paged`)로 표현해, "data 속성은 JS가 읽는 동작 스위치, 클래스는 CSS가 읽는 스타일 스위치"로 역할을 나눴다.

### 페이지 단위 이동과 픽셀 오프셋 기반 상태 관리

페이지 단위(화면에 보이는 만큼씩) 이동 타입은 인덱스가 아니라 `currentOffset`(픽셀) 자체를 상태로 관리한다. 슬라이드 폭이 제각각이라 마지막 페이지의 정지 지점(마지막 슬라이드 오른쪽 끝 = 컨테이너 오른쪽 끝)이 슬라이드 경계와 일치하지 않는 임의의 픽셀 값이 될 수 있어, 인덱스 기반으로는 이 위치를 표현할 수 없기 때문이다. `maxOffset`(전체 슬라이드 폭 합 − 컨테이너 폭)을 미리 계산해두고, 다음/이전 이동마다 `currentOffset ± 컨테이너 폭`을 `[0, maxOffset]` 범위로 클램프한다. 클램프된 값이 이전과 같으면 더 이상 못 움직이는 경계에 도달한 것으로 판단해, 자동재생 중이면 다음 틱에 방향을 반대로 뒤집는다. 이 방식 덕분에 클론 없이도, 그리고 슬라이드 폭이 서로 달라도 마지막 페이지에서 빈 공간이 남지 않는다.

### 인디케이터의 한계와 대안 — dot에서 disabled 버튼으로

슬라이드 개수만큼 dot을 자동 생성하고 `aria-selected`로 현재 위치를 표시하는 방식은 "1장씩 이동"에서는 인덱스와 정확히 대응해 문제가 없었다. 하지만 페이지 단위 이동 타입에 그대로 적용했더니, 근사 함수(`indexAtOffset`, 특정 오프셋 이하에서 가장 뒤에 있는 슬라이드 인덱스를 찾는 방식)가 클램프된 픽셀 오프셋을 슬라이드 하나의 인덱스로 정확히 되짚지 못해 dot이 실제 위치보다 앞선 슬라이드에서 멈춰 보이는 버그가 생겼다. 페이지 단위 이동의 정지 위치는 애초에 슬라이드 하나 단위의 점으로는 정확히 표현할 수 없는 구조적 한계라고 판단해, 이 타입에서는 dot을 없애고 이전/다음 버튼을 슬라이더 좌우 끝에 고정 배치한 뒤 네이티브 `disabled` 속성(`currentOffset`이 0/`maxOffset`에 닿으면 각각 비활성화)으로 위치·경계를 표시하도록 바꿨다. 커스텀 상태 클래스나 `aria-*` 속성을 별도로 관리하지 않고 브라우저가 원래 제공하는 `:disabled` 의미론에 기대는 선택이기도 하다.

### 자동재생 콜백 설계

`setInterval`에는 항상 "함수 자체"를 넘긴다는 원칙을 지켰다. 인자를 미리 고정해서 넘기거나 괄호를 붙여 즉시 실행한 결과를 넘기면, 그 순간의 값이 그대로 봉인되어 이후 갱신된 상태(이동 방향, 오프셋)를 반영하지 못한다. 매 tick마다 최신 상태를 다시 계산하도록 화살표 함수로 감싸 넘기는 방식을 일관되게 적용했다.

```js
autoPlay = setInterval(() => (loopType === "pingpong" ? pagedMove(pingDir) : step(1)), interval);
```

### 자동재생과 사용자 의도의 상태 관리

자동재생 상태(`isAuto`)는 hover와 재생/일시정지 버튼이 동시에 건드릴 수 있는 값이라, 이 둘이 서로 반대 방향으로 상태를 덮어쓰지 않도록 정리가 필요했다. `isAuto` 하나만 "사용자가 재생을 원하는가"라는 단일한 의미로 유지하고, `mouseenter`/`mouseleave`는 이 값을 읽기만 하되 직접 바꾸지는 않는 구조로 설계했다.

### 다중 인스턴스 대응

`setupSliderInstance(sliderEl)` 함수로 전체 로직을 감싸, 슬라이더마다 독립된 상태(현재 인덱스/오프셋, `autoPlay` 타이머, 클론 여부)를 클로저로 갖도록 설계했다. dot 컨테이너가 없는 인스턴스(페이지 단위 타입)에서도 에러 없이 동작하도록 관련 코드를 전부 `if (dotContainer)` 가드로 감쌌다. 같은 함수가 "dot이 있는 타입"과 "없는 타입"을 모두 처리해야 했기 때문이다.

## 결과

- 좌측정렬 무한루프 / 좌측정렬 핑퐁(페이지 단위 이동, 빈 공간 없이 클램프) / 중앙정렬 무한루프(양방향 클론) 3가지 타입을 `data-align`/`data-loop` 속성 조합만으로 지원
- 전체 세트 클론 + 순간 이동(`gsap.set`) 방식으로 마지막→처음 전환이 끊김 없이 자연스러운 무한 루프 완성
- 인라인 커스텀 프로퍼티로 슬라이드별 스타일이 클론 복제에도 안전하게 유지되는 구조
- 페이지 단위 이동에서 인덱스 기반 dot 인디케이터의 한계를 발견하고, 네이티브 `disabled` 속성 기반 경계 버튼으로 대체
- 가변폭 지원, 자동재생+hover/버튼 기반 사용자 제어, 키보드 좌우 이동, 다중 인스턴스 대비까지 유지
- 남은 과제: 스와이프 제스처, 반응형(뷰포트별 슬라이드 폭/보이는 개수 조정)
